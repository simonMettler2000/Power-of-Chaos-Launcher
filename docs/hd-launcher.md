# Local HD card previews

In the black sidebar, open **Settings > Preferences** and choose the generated local HD pack folder. It must contain `yugi-565.tsv`, `kaiba-565.tsv` and `joey-565.tsv`. The launcher includes no artwork or native binaries. A separately built and verified `Components/hd-card-artwork-v1` bundle is also required; it contains the pinned HD `ddraw.dll`, the existing bootstrap `winmm.dll` and all eight attribution notices. Missing or incorrect prerequisites leave the global **Mods > HD card previews** control unavailable, with an explanation. An existing saved selection can always be switched off.

The switch applies to all three games on their next launch. Play captures the checkbox and pack folder before any asynchronous preparation, so edits affect subsequent launches. Splash skipping, character interaction skipping and original aspect ratio remain independent preferences. HD supplies its own 4:3 display path when enabled, with an 800 x 600 logical game frame presented in a 1280 x 960 resizable window using Direct3D 9, RGB565 and the existing unlimited timing settings. The original aspect ratio component bundle and cache remain separate.

Only the chosen game's RGB565 configuration is validated for Play. Metadata is strict UTF-8, at most 1 MiB and 1024 unique positive keys. The header is `POC_HD_VISIBLE_V1`, followed by numeric game 1, 2 or 3 and format 1, separated by a tab. Each remaining row contains a key, an absolute 116000-byte reference path and an absolute 800 x 1160 RGB8 non-interlaced PNG path, separated by tabs. Relative, UNC, device, traversal, control-character and linked paths are refused. Drive-letter paths on mapped volumes are not independently rejected; packs are trusted local inputs. PNG metadata is checked here; the native component independently bounds and decodes the complete image and falls back when it cannot render it.

The launcher validates the pack before preparing any executable. It copies the selected configuration into a private, identity-based HD cache, verifies the native components, configuration and executable, and passes that snapshot through the child's `POC_HD_CONFIG` environment entry. It removes inherited HD configuration from every launch, including when HD is disabled. It never changes the launcher's global environment. Installed executables, archives and saves remain read-only; the child keeps the installed asset directory as its working directory. Referenced local artwork remains in its original pack location and must remain available for the session.

This candidate recognizes complete, unoccluded preview rasters already visible in the final frame and substitutes their local masters at the larger output resolution. Other scenes, small or rotated cards, fades, transitions and unsupported layouts retain the original image. Hidden cards are never identified from private game state. RGB555 and non-Windows hosts are not qualified by this launcher candidate.

Synthetic launcher tests build inert PE-shaped metadata and generated pack headers, and use fake processes. They establish preparation and launch-plan behavior; they do not run original games or prove installed-game rendering. Independent review, exact-commit audit and manual in-game validation remain required before claiming a working game mod.

Run the standalone checks with the pinned .NET SDK: `dotnet run --project tests/PowerOfChaos.HdLauncher.Tests -- <absolute ignored fixture folder>`. Build outputs and fixtures must remain in ignored storage.
